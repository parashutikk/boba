# Анализ требований ИБ и модели угроз

## 1. Нормативное регулирование и классификация

### 1.1 Что такое «класс защищённости» по ГОСТ Р 50739-95?
**Класс защищённости** — это характеристика средств вычислительной техники (СВТ), определяющая способность системы противостоять несанкционированному доступу (НСД). Чем выше класс, тем строже требования к подсистеме защиты.

**Сколько классов определено?**
ГОСТ Р 50739-95 устанавливает **7 классов защищённости** (от 1 до 7), где:
*   **Класс 1** — наивысший (защита от верифицированных угроз);
*   **Класс 7** — базовый (защита при случайном доступе).

---

### 1.2 Чем ГИС отличается от ИСПДн с точки зрения нормативного регулирования?

| Критерий | Государственные информационные системы (ГИС) | Информационные системы персональных данных (ИСПДн) |
| :--- | :--- | :--- |
| **Основной регулирующий документ** | Приказ ФСТЭК № 17 (для ГИС) | Приказ ФСТЭК № 21 (для ИСПДн) |
| **Ключевой классификатор** | Классы защищённости ГИС (1–4) по 17 приказу | Уровни защищённости ПДн (1–4) по 21 приказу |
| **Объект защиты** | Государственные ресурсы, власть, управление, услуги | Персональные данные субъектов (ФИО, СНИЛС, биометрия) |
| **Согласие субъекта** | Не требуется (информация является госсобственностью) | Требуется письменное согласие субъекта ПДн |
| **Уведомление РКН** | Реже (зависит от статуса системы) | Обязательно для большинства операторов |

> **Вывод:** ГИС регулируют доступ к информации государства, ИСПДн защищают права граждан на приватность. Система может быть одновременно ГИС и ИСПДн, если содержит ПДн.

---

### 1.3 Группа мер УПД по Приказу №17 (ФСТЭК России)

**УПД** — меры по управлению доступом и предотвращению НСД (Управление доступом / Предотвращение вторжений).

**4 меры из Приказа №17 (пункты из раздела II «Меры по защите информации»)** :

1.  **УПД.1** — Идентификация и аутентификация субъектов доступа.
2.  **УПД.2** — Управление правами доступа субъектов к защищаемой информации (разграничение доступа).
3.  **УПД.4** — Контроль (мониторинг) действий пользователей (логирование входа, команд, доступа к файлам).
4.  **УПД.6** — Антивирусная защита (в части блокировки попыток внедрения вредоносного ПО, изменяющего права доступа).

## 2. Анализ конкретной уязвимости (Практическая часть)

*Для примера разберем классическую уязвимость **CVE-2023-23397 (Microsoft Outlook)** (принёсшую реальный ущерб десяткам компаний).*

### 2.1 Название и компонент
*   **Название уязвимости:** Повышение привилегий в Microsoft Outlook (New-Tech Elevation of Privilege).
*   **Компонент:** Microsoft Office / Outlook (NetBIOS / SMB протокол).

### 2.2 Механизм уязвимости (Что делает злоумышленник?)
Злоумышленник отправляет жертве специальное письмо с календарной встречей (место встречи указывает на UNC-путь `\\evil.com\file`).

**Механизм:**
1.  Жертва просто открывает письмо (или даже только предпросмотр в панели уведомлений).
2.  Outlook автоматически пытается подключиться к `\\evil.com` по SMB для получения эскиза/иконки.
3.  Клиент Windows автоматически отправляет **NTMLv2-хэш** пароля пользователя серверу злоумышленника.
4.  Хакер перехватывает хэш и взламывает его.
5.  **Результат:** Злоумышленник получает пароль жертвы и доступ к её почте/сети.

### 2.3 Нужна ли аутентификация? (CVSS)
*   **Attack Vector (AV):** Сетевой (Network) — достаточно отправить письмо.
*   **Privileges Required (PR):** Нет (None) — жертва ничего не нажимает.
*   **User Interaction (UI):** Не требуется (Ошибка в CVSS 3.1 — взаимодействие минимально, часто трактуется как Passive).

### 2.4 Какой ущерб наносится?
*   **Конфиденциальность (C):** **Высокий (H)** — утечка пароля и переписки.
*   **Целостность (I):** **Высокий (H)** — хакер может отправлять письма от лица жертвы.
*   **Доступность (A):** Нет (N) — система не падает, но хакер может заблокировать доступ в AD (Active Directory).

### 2.5 Меры из Приказа №17 для снижения риска

| ID меры из Приказа №17 | Конкретная реализация |
| :--- | :--- |
| **УПД.1** (Идентификация/Аутентификация) | Отключение автопополнения NTLM (NTLM-прокси), внедрение Kerberos с ограничением времени жизни билета. |
| **УПД.4** (Контроль действий) | Настройка SIEM-правил: обнаружение аномальных SMB-запросов из Outlook.exe в внешнюю сеть. |
| **УПД.6** (Антивирусная защита) | EDR-агенты (CrowdStrike, Kaspersky), блокирующие выгрузку NTLM-хэшей через сетевые сокеты. |
| **ЗИ.9** (Межсетевое экранирование) | Блокировка исходящего SMB-трафика (порты TCP 139, 445) с пользовательских рабочих станций в Интернет. |
